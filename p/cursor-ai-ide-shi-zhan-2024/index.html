〇、2025 视角开篇

本文写于 2025-12-15，站在 2025 年底回望：Cursor 已经从"AI-first IDE 新星"演化成"事实标准之一"——2024-09 那篇前瞻到 2025 年底大部分已被验证。文中提到的 GPT-5.3 Codex / Sonnet 4.6 / Opus 4.6 / Composer 2 均为 2025 年中后期已发布的模型（不是"未来模型"），2024-09 时它们是"传闻 / 预览"，到 2025-12 已是"日常选项"。

一、为什么选择 Cursor

Cursor（Anysphere）是 2024 年现象级的 AI-first IDE，直接 fork VS Code 内核，把所有 AI 能力内化为编辑器一等公民。2024-2025 年间 ARR 从 0 冲到 5 亿美元，被视为 SaaS 史上最快增长曲线之一。

核心差异点（与传统 VS Code + Copilot 插件方案对比）：

维度CursorVS Code + Copilot
架构fork VS Code，AI 是内核一部分插件机制，AI 是外挂
Tab 补全多行 + 上下文感知，跨文件单行 / 多行，断网即停
Agent 模式原生 Agent + Plan + Debug需通过插件 + MCP 间接调度
代码库理解自动 embedding，存储在云端无索引，每次需手动贴上下文
价格Pro $20/月（含 API 额度）Copilot $10/月（不含 API）

2025-12 更新：Cursor Pro 价格仍为 $20/月（保持 2024 价位），Copilot 在 2025 年提过一次价（$10→$19/月含 API），但 2025-Q3 又调回 $10 单订阅 / $19 含 API 两种档位。

二、5 大核心模式

Cursor 把 AI 协作拆成 5 个独立模式，每个模式有不同的工作流：

模式触发方式核心场景
AgentCtrl+I端到端任务：修 Bug / 写功能 / 重构
PlanShift+Tab 切换复杂任务先出方案再动手
Debug调试菜单难复现问题，先假设后验证
AskCtrl+L问答 / 解释代码，不修改文件
Composer独立面板跨文件大规模改写

2.1 Agent 模式

Agent 是 Cursor 的"主菜"，由三个组件协同：

1
2
3

Agent = Instructions（system prompt + 规则）
      + Tools（文件编辑 / 代码库搜索 / 终端执行 / MCP）
      + Model（Composer 2 / GPT-5.3 Codex / Claude Sonnet 4.6 / Opus 4.6）

实战中 Agent 自动处理这些事：

  • 自动分析项目结构（@src/ 包含文件夹）
  • 自动跑 npm test 验证
  • 自动应用 diff，让用户 Ctrl+Y 接受
  • 自动 commit（可关闭）

2.2 Plan 模式

复杂任务必须先开 Plan 模式——Agent 会：

  1. 分析当前代码库
  2. 提出 2-3 个澄清问题（“用 JWT 还是 session？"）
  3. 生成可审阅的实施计划
  4. 等待用户确认后才动手

经验法则：修改超过 3 个文件的任务，先 Plan。

2.3 Debug 模式

Debug 模式与传统 console.log 调试的差异：

  • 不会立即写代码，而是先提出假设
  • 自动加日志语句
  • 利用运行时信息反推根因
  • 再做针对性修复

适合：偶发性 bug、性能毛刺、并发问题。

2.4 Ask 模式

Ask 不修改任何文件，专用于：

  • “解释这段代码为什么这么写”
  • “这个函数的调用链是什么”
  • “对比 A 和 B 两种实现方案”

三、模型选择与 MAX 模式

Cursor 提供 5 类模型，按"质量-成本"梯度排列：

模型上下文定位价格
Composer 2 Fast200kCursor 自研 agentic 模型Pro 套餐含
GPT-5.3 Codex272k（MAX 1M）OpenAI 编码专精Pro + API 额度
GPT-5.4272k（MAX 1M）OpenAI 综合旗舰Pro + API 额度
Sonnet 4.6200k（MAX 1M）Anthropic 日用Pro + API 额度
Opus 4.6200k（MAX 1M）Anthropic 顶级Pro + API 额度

MAX 模式会把上下文窗口撑到模型原生最大值（如 Sonnet 4.6 MAX = 1M），适合"整个代码库做大规模迁移"这类任务。但 MAX 按 token 计费，Pro 套餐会加收 20% 附加费。

实战配比建议：

  • 日常 80%：Composer 2 Fast（快、便宜、够用）
  • 中等复杂度：Sonnet 4.6（性价比最优）
  • 大改动 / 难 Bug：Opus 4.6（最强但慢）
  • 特定场景：GPT-5.3 Codex（编码任务特化）

四、Pro $20/月套餐成本核算

Pro 套餐结构：

1
2
3

Pro $20/月 = Auto 用量（Composer 2 + Auto 模式）
           + API 用量（其他模型，按 token 计费）
           + 至少 $20 API 额度

On-Demand 模式开启后，套餐额度用完按 API 费率继续扣费。月成本从 $20 到 $100+ 都有可能，取决于你用 MAX 模式 / Opus 4.6 的频率。

个人建议：

  • 默认 Auto 模式，把"难任务"显式指定模型
  • 关闭 On-Demand，避免月底天价账单
  • 大规模重构任务用本地 Worktree 模式（下面有）

五、代码运行环境：Local / Worktree / Cloud

Agent 执行代码有 3 个环境：

环境适用场景优势
Local当前工作区直接改最直接，但风险大
WorktreeGit worktree 隔离分支主分支不受影响，可并行
Cloud云端代理长任务 / 离开电脑时跑

关键习惯：所有"会改超过 5 个文件"的任务都用 Worktree，结束后 git merge 回主分支。

保护机制（默认开启，建议全开）：

  • External-File Protection：禁止 Agent 写工作区外文件
  • File-Deletion Protection：禁止 Agent 自动删文件
  • MCP Tools Protection：禁止 Agent 自动跑 MCP 工具
  • Browser Protection：禁止 Agent 自动开浏览器

# 用户编码规范与重构指南

## 1. 交互与基础规范
- 中文优先：回答和注释用中文
- 代码颗粒度：超过 20 行考虑聚合或拆函数
- 避免深层嵌套，优先卫语句

## 2. 重构
- 小步重构：每次只做一个改动，频繁提交
- 命名拒绝缩写（约定俗成的 i 除外）
- 注释解释"为什么"而非"做什么"

十、Java 跳转配置（提升 IDE 体验）

Cursor 继承自 VS Code，Java 跳转默认不完美。在 settings.json 加：

HTTP 兼容模式：默认 HTTP/2，企业代理环境若出现"流式响应被缓存"或"双向流不支持"等错误，可降级到 HTTP/1.1。

十二、订阅与计费陷阱

  • On-Demand 默认 Disabled——开启后套餐用完继续按 API 费扣，月底可能$100+
  • 隐私选项 Data Sharing Enabled 默认开启——你的代码、提示词会用于训练，生产代码建议关闭
  • Commit Attribution 默认开启——Agent 生成的 commit 会标记 “Made with Cursor”，团队项目看公司文化决定
  • Cursor Tab 默认开启——多行补全比 Copilot 激进很多，新用户可能觉得"太自动”，可在 Settings > Cursor Tab 调灵敏度

十三、总结

Cursor 把"AI 是 IDE 一等公民"这件事做对了，编辑器体验 + Tab 补全 + Agent 闭环是它的护城河。但Pro $20 套餐只是个入门价，真要 MAX 模式 + Opus 4.6 跑大任务，月账单 $100+ 是常态。

实战建议：

  1. 新项目直接用 Cursor 起步，省去 30% 重复劳动
  2. Worktree 模式是默认习惯，保护主分支
  3. 规则文件按团队规范沉淀，复用率最高的"知识资产"
  4. On-Demand 默认关闭，控制成本
  5. MAX 模式慎用，留给大改动

十四、2025→2026 模型升级与生态走向

站在 2025-12 收尾，回望 2024-09 时点 Cursor 模型表里那些"还是预览/即将推出"的型号，到 2025 年底已全部 GA：

模型2024-09 时点2025-12 时点
Composer 2 / Composer 2 Fast尚未推出日用首选（Cursor 自研 agentic 模型）
GPT-5.3 Codex预览OpenAI 编码主力（含 MAX 1M 选项）
GPT-5.4传闻OpenAI 综合旗舰（替代 GPT-4o/4.5 地位）
Sonnet 4.6Sonnet 3.5 刚发布Anthropic 性价比最优（替代 3.5/4.5 位置）
Opus 4.6Opus 3 已发布Anthropic 顶级（慢但最强）

2025 实战配比建议（相对 2024-09 原文"日常 80% Composer 2 Fast、中等 Sonnet 4.6、难 Bug Opus 4.6"基本一致）：

  • 日常 80%：Composer 2 Fast（快、便宜、够用）—— 2025 年自研模型成熟后这个比例更稳
  • 中等复杂度：Sonnet 4.6（性价比最优）—— 与 2024-09 判断一致
  • 大改动 / 难 Bug：Opus 4.6（最强但慢）—— 与 2024-09 判断一致
  • 特定场景：GPT-5.3 Codex（编码任务特化）—— 2025 年 OpenAI 编码模型已能跟 Sonnet 4.6 掰手腕

2026 展望（仅供参考，不属于"2025 已验证"内容）：

  • Cursor 可能跟进"按席位 + 按用量"双轨计费，避免 On-Demand 的天价账单争议
  • Composer 3 可能在 2026 年发布，进一步压缩对外部模型（GPT-5.3 / Sonnet 4.6）的依赖
  • AI IDE"五强格局"（Cursor / Trae / Claude Code / Copilot / Windsurf）短期不会破
